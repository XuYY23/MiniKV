# 01 · 工程骨架与公共类型

## 位置

MiniKV 是「单机 LSM 引擎 + 分布式 Raft 服务」。嵌入式引擎需要稳定的对外 API 与错误模型；Flush、Compaction、Raft 状态机都复用同一套 `DB` 接口语义。

## 目录结构（引擎侧）

```text
include/minikv/     对外头文件（稳定 API）
src/engine/         引擎实现（WAL / MemTable / …）
src/env*.cc         文件与目录的 POSIX 封装
tools/              CLI
tests/              模块测试
docs/               设计与教程
```

对外只依赖 `include/minikv/`：`db.h`、`options.h`、`status.h`、`slice.h`。内部模块通过 `src/` 相对包含。

## 四个公共类型

### Status

所有可能失败的操作返回 `Status`，而不是抛异常或靠 errno 裸透传。

- `OK`：成功  
- `NotFound`：键不存在或已被删除  
- `Corruption`：数据损坏（如 WAL 校验失败）  
- `IOError` / `InvalidArgument`：环境或参数问题  

`status.ok()` 区分成功和失败，具体错误码表达失败类别。

### Slice

非拥有的字节视图：`(ptr, len)`。读写路径大量传递 `Slice`，减少临时 `std::string`。`Slice` 不延长底层缓冲区的生命周期。

### Options

- `write_buffer_size`：MemTable 内存阈值，触发 Flush  
- `sync`：默认写选项是否 fsync（单次写入可用 `WriteOptions::sync` 覆盖）  
- `create_if_missing` / `error_if_exists`：打开行为  

### DB

```text
Open → Put / Get / Delete → Close
```

`DB` 是抽象接口，`DBImpl` 是当前单机实现。分布式状态机调用同一套语义。

## 设计取舍

| 选择 | 原因 |
|------|------|
| 同步 API + 内部互斥 | 语义简单明确，优先保证正确性 |
| Status 而非异常 | 热路径可控，错误可预期传递 |
| Env 抽象文件 IO | 测试与移植时只替换环境层 |
